# Orthodoxou Ferry Monitor

Стежить за наявністю місць на порон Пірей ↔ Лімасол (сайт бронювання Orthodoxou / CertusBook)
і пише в Telegram, щойно місця з'являються.

## Як це працює

Сайт не має відкритого API і не віддає результати без JavaScript, тому бот керує справжнім
браузером (Playwright): обирає порти, ставить дату в календарі, тисне «Пошук» і читає
індикатори наявності в списку рейсів.

Для кожного рейсу сайт показує три кружечки — **пасажир**, **авто**, **каюта** — і колір
означає:

| Колір    | Грецькою        | Статус         |
|----------|-----------------|----------------|
| зелений  | Ικανοποιητική   | є місця        |
| жовтий   | Οριακή          | мало місць     |
| червоний | Μηδενική        | немає          |

Бот зберігає попередній стан у `state.json` і надсилає повідомлення **лише коли статус
змінився** з «немає» на «є / мало». Тобто спаму не буде.

## Якщо перевірка зламається

Тиша від бота мала б означати «місць немає». Але сайт може змінитися чи впасти — і тоді
тиша означала б «бот осліп», що виглядає однаково. Тому є два запобіжники:

- перевірка окремої дати не пройшла → повідомлення **один раз**, коли вона зламалась, і ще
  раз, коли відновилась (стан помилки теж лежить у `state.json`, тому повтори не спамлять);
- впав увесь запуск і скрипт не встиг нічого надіслати → окремий крок workflow пише в
  Telegram із посиланням на журнал.

## Налаштування

1. **Telegram-бот.** Напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → отримаєте токен.
   Далі відкрийте свого бота і натисніть **Start** (інакше він не зможе вам писати).
2. **Chat ID.** Відкрийте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — у відповіді
   знайдіть `"chat":{"id":...}`.
3. У репозиторії на GitHub: **Settings → Secrets and variables → Actions → New repository secret**
   — додайте `TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID`.

Щоб сповіщення отримувала не одна людина, впишіть кілька ID — через кому або з нового
рядка, обидва варіанти працюють. Кожен одержувач має спершу сам натиснути **Start** у бота.
Альтернатива — створити групу, додати туди бота і вказати ID групи (він відʼємний).

Готово. Далі GitHub Actions запускає перевірку кожні 30 хвилин безкоштовно.

## Що саме моніторити

Змінюється у `.github/workflows/monitor.yml`, блок `env`:

```yaml
ROUTE_FROM: ATH      # ATH / PIR (Афіни, Пірей) або CYP / LMS (Кіпр, Лімасол)
ROUTE_TO: CYP
DATES: "2026-08-24,2026-08-27"
WATCH: pax           # pax (пасажир), cabin (каюта), vehicle (авто) — через кому
```

## Запуск локально

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m playwright install chromium

# які взагалі дні мають рейси
.venv/bin/python monitor.py --from ATH --to CYP --list-days

# перевірка (без токенів просто друкує в консоль)
.venv/bin/python monitor.py --dates 2026-08-24,2026-08-27 --watch pax
```

Корисні прапорці: `--headed` (показати браузер), `--always-notify` (слати звіт щоразу,
навіть якщо змін немає).

## Важливо знати

- Розклад рідкий: у вікні 24–27.08.2026 рейси є лише **24.08** і **27.08**.
- Заплановані GitHub Actions вимикаються автоматично, якщо в репозиторії 60 днів немає
  активності. Для короткого моніторингу це не проблема.
- Cron у GitHub Actions не хвилина-в-хвилину: можливі затримки до 10–15 хвилин у години пік.
